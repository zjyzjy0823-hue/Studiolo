## 已排除的假设（重要，别浪费时间在这上面）

我一开始以为是 agent-node 卡死，**实测否定了**：

- 审计日志（`~/.hermes/logs/studiolo-audit-node.log`，时间戳为 UTC）显示节点在整个 22:22–22:29 期间**连续在发帧**：14:27 这一分钟 641 帧、14:28 一分钟 1057 帧，除心跳外没有任何 >8 秒的间断
- Core 侧审计（`studiolo-audit-core.log`）与节点侧逐条对齐：**按 seq 比对，缺失 0 条**
- 节点进程的 TCP 到 Core 与到 Hermes 均 ESTABLISHED，事件循环正常（`sample` 显示在 kqueue 等待）
- 因此：**Hermes → 节点 → Core 全程是通的**，帧确实送到了 Core

## 现场事实（实测）

1. 22:22:14.933（UTC 14:22:14）节点向 Core 发 `SessionStreamReplay`
2. 22:22:15 之后手机客户端进入「已重连 · 切换至快照」状态，并显示三个点的运行中指示
3. 22:22–22:29 期间 Hermes 侧正常产生了多轮助手回复（审计里 run=2cb542bc 等有大量 ThoughtDelta/TextDelta），节点与 Core 都收到了
4. **手机屏幕上这些消息一条都没出现**；22:26 的截图仍是「已重连 · 切换至快照」+ 三个点
5. 22:24:24 节点拒绝了客户端的一次 prompt，报 `ValueError: 当前会话已有任务运行中`（agent_node/adapters/hermes_ws.py:869）——说明适配器侧认为该会话还有活跃回合
6. 22:29:14 手动重启节点后，客户端立刻重新同步，**历史全部正常渲染**（说明数据没坏，是客户端/转发侧的状态问题）
