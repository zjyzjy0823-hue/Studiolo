# 任务书：P4c —— 打开会话时的「空占位闪烁」

## 一、真机现象（0.9.6 epoch，2026-11-24 21:40）

打开一个已有会话，时间线：

| 时刻 | 界面 |
|---|---|
| 第 3 秒 | **12 行空占位，每行写着「用时未记录」**，没有任何正文 |
| 第 12 秒 | 正常：1 个助手块 + 14 条工具条目，「用时未记录」0 次 |

即：**打开会话先闪 10 秒空壳**，然后才变成正确内容。

## 二、三个必须修的点

### 1. epoch 消息不得出现「用时未记录」

`WorkLog.vue` 的 `label` 里，`epochSnapshot` 为真时走 `formatWorkLogDuration(...) || '工作步骤'`；
为假时仍会 fallback 到 `'用时未记录'`。

要求：**epoch 路径的消息，无论 `epochSnapshot` 标志是否就绪，都不允许出现「用时未记录」**。
判定不能用单个布尔，改用「这条消息来自 epoch 同步」的稳定标识（如消息上已有 `syncMode`/来源字段），
或者把 fallback 文案从 `'用时未记录'` 改成中性文案（`'工作步骤'`）。

### 2. 空消息块不要渲染

正文为空、`toolCalls` 为空、`thought` 为空的 assistant 消息**整块跳过**，不要渲染成一行 WorkLog。
这是那 12 行空占位的直接来源（快照里 turn 有壳、内容还没到，客户端把壳画出来了）。

要求：在投影阶段（`epochSnapshot.ts` 或 thread 的行构造处）过滤掉这种空壳；
**只在 epoch 路径过滤**，legacy 行为不变。

### 3. 缓存要真的先渲染

`messageCache.read` 已经把 rows 写进 `messagesBySession`，但真机上第 3 秒没看到缓存内容。
请自查并修复「缓存读到了但没显示」的链路，要求：

- 缓存命中时，**首帧就渲染缓存消息**（不等网络）
- 网络快照到达后替换（不叠加、不重复）
- 若缓存行缺少渲染所需字段导致被当成空壳过滤，请在读取时补齐，而不是丢弃

## 三、测试（真跑并贴输出）

1. 空壳消息（无正文/无工具/无思考）在 epoch 投影后被过滤，数量为 0
2. epoch 消息的 WorkLog 文案**永远不等于**「用时未记录」（含 `epochSnapshot=false` 的过渡态）
3. 缓存命中 → 首次渲染即有消息（用可注入的假存储与假网络，断言渲染顺序：cache 先、snapshot 后替换）
4. `node --test tests/` 全绿（现有 213 项不得减少）、`npx vue-tsc --noEmit` exit 0

## 四、禁止

- 不改 legacy 渲染与 legacy 数据路径
- 不改 `src-tauri/`、`backend/`、`agent-node/`
- 不引入新依赖、不 commit、不打包
