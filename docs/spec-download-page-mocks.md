# 任务：PC 端「下载」独立页面 —— 出 4 个布局样例（只要静态 HTML）

## 背景

现在桌面端点侧栏的下载图标会 `go('Settings', false, 'downloads')`，直接跳进设置页里的「下载记录」。
产品上要改成**独立的一级页面**（侧栏图标 → 直接打开下载页，不再进设置）。

本轮只做**视觉/布局样例**，不接真实数据、不改现有代码、不动路由。

## 交付物

在 `~/Projects/riri-mocks/download-page/` 下产出 **4 个独立 HTML**（可共用一份 CSS）：

```
index.html        # 导航页，四张卡片分别链接到 a/b/c/d
a-table.html      # 方案 A：数据表格型（桌面原生感）
b-grid.html       # 方案 B：卡片网格型（缩略图优先）
c-split.html      # 方案 C：双栏（列表 + 右侧预览/详情）
d-compact.html    # 方案 D：紧凑清单型（类似 Finder / 下载器）
mock.css          # 共用样式（设计 token 参考 design/studiolo-redesign/*.css）
```

每个页面都要是一个**完整可截图**的桌面应用视图（1280×800 视口刚好），包含：

- 顶部应用壳：左侧窄图标栏（下载图标高亮为当前页）、顶部标题区
- 页面标题「下载」+ 副标题（例如「本机保存的文件，只在这台设备上」）
- 工具条：搜索框、类型筛选（全部/图片/文档/压缩包/安装包/其它）、时间筛选、排序、右侧「刷新」「在文件夹中打开」等
- 批量操作条（选中时出现的样式可以先静态展示）
- 列表/网格主体：**至少 8 条真实感样例数据**，字段包含
  - 文件名（中文+英文混排，含扩展名）
  - 类型图标（按扩展名区分颜色/形状）
  - 大小（如 12.4 MB）
  - 来源（会话名，如「上个会话怎么消息都发不出…」/「邮箱巡检 · Nov 27」）
  - 时间（今天 14:23 / 昨天 / 11-25）
  - 状态：已完成（正常）、下载中（带进度，例如 42%）、失败（可重试）
- 行/卡片操作：打开、在文件夹中显示、重新下载、删除（图标按钮 + hover 提示）
- 空状态样式（可以在页面底部单独展示一块）
- 底部状态栏（沿用现有：Core 状态 + 版本号）

## 设计约束（必须遵守）

- **只用现有设计语言**：`mat-solid` 卡片、`--surface/--line/--text/--accent/--r-lg/--shadow-pop` 等 token、字号 `calc(Npx * var(--fs))`；不要引入新的配色体系或圆角语言
- 支持亮/暗：用 `data-mode="light|dark"` 切换（样例里亮色为主，至少 A 方案再出一份暗色）
- 中文界面，文案简洁；不要用 emoji 当图标，用内联 SVG（可以复用 lucide 风格的 path）
- 不写 JS 逻辑（hover 用 CSS 即可），但要有 hover/focus 态的样式

## 四个方案各自的侧重点

| 方案 | 布局 | 适合 | 关键差异 |
|---|---|---|---|
| A 表格 | 单列数据表，列可对齐：文件 / 来源 / 大小 / 时间 / 状态 / 操作 | 信息密度高，像桌面软件 | 表头可排序的视觉暗示 |
| B 网格 | 2–4 列卡片，图片类显示缩略图占位，其它显示大图标 | 图片/安装包为主 | 顶部一排统计卡（总数/占用空间/本周新增） |
| C 双栏 | 左列表（窄，可滚动）+ 右详情（大预览 + 元数据 + 操作按钮） | 想看清文件信息 | 右侧详情含「来源会话」跳转 |
| D 紧凑清单 | 单列紧凑行，分组标题（今天/昨天/更早），行高更小 | 快速浏览，像 Finder | 分组 + 行内极简操作 |

## 验收

- 四个 HTML 都能直接在浏览器打开，1280×800 下无横向滚动、无文字溢出
- 截图对比时能一眼看出四种方案的结构差异
- 不修改仓库里的任何现有文件（只新增 `~/Projects/riri-mocks/download-page/`）
