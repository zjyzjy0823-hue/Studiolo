# 任务书：P13 —— 发送不跟手（消息消失一会儿才出现）

## 一、现象

点发送后：
1. 消息**先不出现**（或闪一下就没）
2. 过一会儿才作为正式消息出现
3. **带图片时消失更久**

## 二、根因（已定位到代码）

1. 发送时客户端**确实**先插了一条乐观消息：`fleet.ts:3594` `delivery: 'sending'`（带附件时 `:4006`）
2. 但只要这期间发生一次历史/快照刷新，**新列表是按服务端返回重建的**（`fleet.ts:2090` 起，`frame.messages.map(...)`）
3. 服务端此刻还没落库这条消息 → 数组里没有它 → 乐观消息被**丢弃**
4. 等服务端落库、下一次刷新匹配上（`fleet.ts:2102` 转 `delivery: 'sent'`）才回来

带附件更久，因为上传耗时在 `sending` 期间，暴露窗口更长。

## 三、修复原则（一句话）

**本地的待发消息是本地事实，任何服务端刷新都不许删它。**

## 四、要做的

### 1. 合并不变式（主要修复）

在历史/快照刷新重建数组的地方（`fleet.ts` 中 `frame.messages.map(...)` 之后、写入
`messagesBySession` 之前）追加：

```
保留所有 delivery === 'sending' 或 'failed' 的本地行，
如果它们在服务端返回的列表里没有对应项（按 requestId 或内容指纹匹配），
则按 createdAt 顺序追加到数组末尾（或其原始相对位置）。
```

要求：

- 匹配优先用 `requestId`；没有则用现有 `sameTurnContent`
- 一旦服务端回显匹配成功 → 转 `delivery: 'sent'`（这条已存在，保持）
- 发送失败 → 保持 `failed` 且**不被刷新删掉**（用户要能重发）
- 只对 `role === 'user'` 的待发行生效

### 2. 发送中的视觉反馈

- `delivery === 'sending'` 的气泡显示「发送中…」状态（现有组件若有此状态就复用；没有则加一个轻量标记，**不要改整体样式**）
- 附件上传期间显示「上传中…」，不要显示为已发送

### 3. 不做的事

- 不改成"等服务器返回再显示"（那就更不跟手了）
- 不改服务端、不改 Core、不改节点
- 不动 P11 的实时帧映射与 P6 的系统通知分类

## 五、测试（真跑并贴输出）

1. 有 `sending` 行时来一次历史刷新（服务端不含该条）→ **该行仍在**，且仍为 `sending`
2. 服务端回显后 → 该行变 `sent`，**不重复**（数组里只有一条）
3. 两条待发 + 一条已发送，刷新后顺序正确（按 createdAt）
4. `failed` 行刷新后仍存在
5. 附件消息：`sending` 期间刷新不丢，`artifacts` 仍在
6. `node --test tests/` 全绿（不得减少）、`npx vue-tsc --noEmit` exit 0
